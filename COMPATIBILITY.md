# Compatibility Contract

The migration preserves the `/v1-secrets` routes, schemas, action names, JSON field names, loopback port `8181`, 32-byte local-key format, AES-256-GCM payload format, signatures, rewrap envelopes, Vault transit behavior, and the `secrets-api` executable name expected by preserved Server orchestration. API responses are always local JSON; the inherited browser-only HTML writer and its external scripts were intentionally removed.

The source under `compat/controlplane` retains only the inherited API and client types required by that compatibility contract. It is compiled through the neutral local module path and is not a PastureStack product identity. Its original Apache-2.0 license, origin, revision, authorship, and copyright remain explicit in that directory. The historical `DEFAULT_CATTLE_SECRETS_API_DEBUG` environment variable remains a secondary alias for existing installations; use `PASTURESTACK_SECRET_DELIVERY_API_DEBUG` for new configuration.

The `none` backend remains only for protocol fixtures and controlled migration tests. The backend is disabled by default and requires the explicit `--allow-insecure-none-backend` flag or `ALLOW_INSECURE_NONE_BACKEND=true`. Its weak legacy MD5 signature is intentionally rejected and replaced by SHA-256 in `v0.3.0`; data relying on that insecure signature format must not be treated as authenticated. Production operation must use `localkey` or a separately reviewed Vault configuration. Local key files must be regular, non-symlink files with no group or other permissions on Unix systems. Do not expose port `8181` outside the Server container or host loopback interface.

Vault transit requests use a 30-second client timeout and preserve TLS configuration supplied through supported Vault environment variables. When token metadata supplies `storage_dir`, retrieval and deletion accept only paths generated by this service in `storage_dir/v1-secrets/<SHA-256>`; arbitrary Vault paths are rejected.

Before release, validate create, bulk create, rewrap, bulk rewrap, purge, malformed signatures, malformed public and private keys, oversized and trailing JSON, Vault path confinement, Server process supervision, database key continuity, restart persistence, rollback, and backup restore in an isolated VM.
